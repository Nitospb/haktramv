# Проверка уровня прогноза после публичного 0,88232

Пользователь предложил проверить рост около 4%. Здесь это трактуется как увеличение нового файла `submission_01_direct.csv` на 4%, а не как доказанный рост реального пассажиропотока относительно октября.

| Файл | Изменение к новому прогнозу | Объём к публичному лучшему |
|---|---:|---:|
| `submission_direct_plus4.csv` | +4% до округления | −1,47% |
| `submission_direct_best_volume.csv` | +5,5515% с точным сохранением заданной суммы | 0% |

Второй файл сохраняет почасовую форму новой модели с поправкой на округление, но получает общий объём старого лучшего: 12 902 502. Используется только сумма старого прогноза. Это не среднее двух прогнозов и не подстановка скрытого целевого объёма.

Если подразумевалось +4% **выше старого лучшего**, новому прогнозу нужен множитель 1,097736, то есть примерно +9,77%. Такой отдельный вариант сейчас не создавался.

Локальные проверки не подтверждают постоянную прибавку 4%:

| Полное окно 61 день | Исходный новый прогноз | Новый прогноз +4% |
|---|---:|---:|
| Июль–август | 0,78953 | 0,75568 |
| Август–сентябрь | 0,89582 | 0,88192 |
| Сентябрь–октябрь | 0,89994 | 0,89204 |

Поэтому файлы являются диагностическими тестами гипотезы об уровне ноября–декабря, а не подтверждёнными улучшениями. Если при равном суммарном объёме скор всё равно заметно ниже 0,89402, одного общего множителя недостаточно: потребуется исследовать распределение по маршрутам, датам и часам. Даже улучшение от +4% само по себе не означает, что реальный пассажиропоток вырос на 4%.

Оба файла имеют 14 640 уникальных ключей, целые неотрицательные прогнозы и разделитель `;`. Лучший `outputs/submission_best.csv` не изменён. Воспроизведение без обучения: `python3 probe_direct_level_20260927.py`. Все рассмотренные локальные множители и результаты сохранены в `validation.csv`; хеши — в `report.json`.
