## Клонирование и запуск

Крупные исходные таблицы и архив признаков хранятся через Git LFS.

```bash
git lfs install
git clone https://github.com/Nitospb/haktramv.git
cd haktramv
git lfs pull
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-studio.txt
```

Готовый лучший прогноз: **[`outputs/submission_best.csv`](outputs/submission_best.csv)**.
Он содержит 14 640 строк и имеет подтверждённый пользователем скор 0,89214.
Проверка артефакта и воспроизведение согласования из сохранённых прогнозов:

```bash
python reproduce_best.py --output outputs/submission_reproduced.csv
```

В `data/labels/` сохранена почасовая агрегированная разметка, в
`data/test_submission.csv` — шаблон. Сырые `train.csv` и `test.csv` с отдельными
транзакциями исключены через `.gitignore`. Каталог `data/features/` содержит
переданные внешние признаки и агрегаты работы транспорта; `data/enriched/` —
подготовленные признаки. Данные карт пассажиров и отдельные транзакции не
публикуются. `outputs/studio/` хранит модели, отчёты и прогнозы экспериментов.

Для повторного обучения используются локальные `data/` либо путь из
`TRAM_DATA_DIR`. Последовательность, необходимая для v8:

```bash
python feature_models.py
python ensemble_features.py
python service_models.py
python event_experts.py
python reconcile_forecasts.py
```

`reproduce_best.py` восстанавливает уже проверенный прогноз без обучения.
Повторное обучение может дать небольшие численные отличия между платформами.

## Данные и проверка

Используются выданные агрегаты `labels_day_train.csv` и `labels_day_test.csv`.
Пропущенные ключи маршрут × дата × час дополняются нулями. Маршрут 5 отсутствует
в обоих агрегатах, поэтому прогноз для него равен нулю.

Метрика: `max(0, 1 - sum(abs(y - prediction)) / sum(y))`.
Каждая проверка прогнозирует два полных месяца без доступа к их целевым значениям:

- январь–апрель → май–июнь;
- январь–июнь → июль–август;
- январь–август → сентябрь–октябрь.

В первоначальном эксперименте выбор весов использовал первые два отрезка,
а сентябрь–октябрь был отложенной проверкой. В последующих циклах эти периоды
использовались для подбора и уже не являются независимым тестом. Выбранные
модели переобучаются на январе–октябре для ноября–декабря. Скрытая метрика
соревнования локально недоступна.

## Модели

`advanced_train.py` сравнивает 12 сезонных профилей (средние/медианы по маршруту,
типу дня и часу), 6 регуляризованных регрессий с годовой сезонностью и
8 конфигураций CatBoost. Ансамбль имеет неотрицательные веса с суммой 1.

Признаки CatBoost: маршрут, час, день недели, тип рабочего/выходного дня,
праздники, месяц, день месяца, время, годовые синус/косинус, летний период.
Для переноса выходных используется календарь 2025 года:
https://www.consultant.ru/law/ref/calendar/proizvodstvennye/2025/

Регрессии по единственному неполному году могут плохо экстраполировать сезонность;
их полезность оценивается на временных проверках. Мощность компьютера сама по себе
не гарантирует качество прогноза или достижение 0,95.

## Запуск на сервере

```bash
TRAM_DATA_DIR="$PWD/data" OPENBLAS_NUM_THREADS=2 .venv/bin/python -u advanced_train.py
```

Результаты находятся в `outputs`: `submission.csv`, `advanced_report.json`,
`advanced_metrics.csv`, `holdout_predictions.csv`, `route_metrics.json`,
сохранённые модели и кеши прогнозов. `advanced_training.log` содержит ход текущего
запуска. Финальный CSV содержит ровно 14 640 строк, разделитель `;`.

## Пересмотр после независимой проверки

Первоначальный ансамбль показал 0,7358 на сентябре–октябре. Этот результат
сохранён в `advanced_report.json`, а не заменён оценкой после подбора.
`finalize_model.py` исключает нестабильные регрессии годовой сезонности и Poisson,
подбирает веса по всем трём отрезкам и пересоздаёт основной `submission.csv`.
Его результаты в `production_report.json` являются **оценками на данных подбора**,
независимой проверки после этой корректировки нет. Для полного повторения
запустите `advanced_train.py`, затем `finalize_model.py` с той же переменной
`TRAM_DATA_DIR`.

Кеши относятся к текущему коду и данным. При изменении параметров, признаков или
данных используйте новый каталог результатов или удалите соответствующие кеши.

## Второй цикл экспериментов

`research_v2.py` обучает CatBoost на исторических датах начала прогноза с
горизонтами 1–61 день. Признаки включают профили за 14/28/56/112 дней, сезонные
аналоги, недавние изменения и горизонт. Проверка с заменой будущих целевых
значений подтвердила независимость прогнозных признаков от будущих ответов.
Сравниваются предсказание абсолютного уровня и отношения к недавнему уровню.

Лучший по среднему результату трёх двухмесячных отрезков вариант — сезонный
профиль `adaptive_28_0.5`: учитывает лето и остальные месяцы, затем корректирует
уровень по отношению фактического и типичного потока маршрута за последние
28 дней с коэффициентом сглаживания 0,5.

Оценки выбранного варианта: июль–август 0,8093; август–сентябрь 0,8749;
сентябрь–октябрь 0,8942. Отрезки частично пересекаются и использовались для
подбора — независимыми тестовыми оценками они не являются.

`refine_profiles.py` дополнительно проверяет 80 вариантов коррекции по типу дня
и времени суток. Выбранный по августу–октябрю вариант даёт 0,8931 на
сентябре–октябре и 0,9009 на одном октябре. Оценка одного месяца не подменяет
двухмесячную оценку.

Новый основной кандидат: `outputs/studio/v2/submission.csv` (локальная копия),
на сервере — `outputs/v2/submission.csv`. Все параметры и оценки сохранены в
`report.json`, `metrics.csv`, `refinement_report.json`, `refinement_metrics.csv`
рядом с прогнозами. Для воспроизведения запустите `research_v2.py`, затем
`refine_profiles.py` с тем же `TRAM_DATA_DIR`.

Цель 0,95 по 1−WAPE не достигнута. R² — другая метрика: прежний ансамбль уже
имел R²=0,9589 при 1−WAPE=0,8648. Сравнение сохранено отдельно в
`outputs/metric_comparison.json`; оно не доказывает достижение целевой метрики.

Она записана в `outputs/leaderboard_results.json` отдельно от локальных оценок.
Соответствие файлу v2 предполагается по последнему выданному кандидату;

`research_v3.py` проверяет профили с экспоненциальным снижением веса старых дат,
объединение будней, разделение суточного объёма и почасовой формы, а также
сглаженный выбор моделей по маршрутам. `season_gate.py` подбирает переключение
между свежей историей того же сезона и длинным сезонным профилем.

Рекомендуемый следующий кандидат —
`outputs/studio/v3/submission_season_gate.csv`. В нём 75% прогноза даёт модель
суточного объёма и почасовой формы с периодом полураспада весов 56 дней,
25% — предыдущая v2; при смене летнего/нелетнего сезона используется v2.
Все профили обучаются только на доступной к старту прогноза истории.

Параметры выбраны по маю–июню, июлю–августу, августу–сентябрю и
сентябрю–октябрю. На этих отрезках результат соответственно 0,86445, 0,81417,
0,87569 и 0,89422. Октябрь не участвовал в выборе конфигурации переключения:
его **одномесячная** диагностическая оценка 0,90698 против 0,89460 у v2.
Ранее октябрьские результаты уже исследовались, поэтому это не новый полностью
независимый тест. Реальная оценка нового файла ещё неизвестна.

Повторение на сервере: после `research_v2.py` выполните `research_v3.py`, затем
`season_gate.py`. В `outputs/v3/gate_report.json` сохранены параметры и оценки,
в `outputs/v3/model_history.csv` — агрегированная обучающая история.

## Дополнительные признаки: v4

`feature_models.py` объединяет дневной календарь/погоду, учебные признаки,
маршрут-часовой календарь ремонтов и событий, статический GTFS и пересадочные
характеристики. Каждое соединение проверяется на уникальность ключей; итоговая
сетка содержит 87 600 строк за весь 2025 год. Сезонный индекс Москвы получен
из переданного файла за 2022–2024 годы. Транзакционные показатели текущего
прогнозируемого часа в признаки не входят.

Погода и события ноября–декабря в предоставленных данных ретроспективные.
Поэтому это эксперимент с предоставленными внешними признаками, а не
полностью воспроизводимый прогноз из информации, известной 31 октября.
GTFS — статический снимок, учебный календарь содержит приближения.

Проверены 8 конфигураций CatBoost и 18 сезонных шаблонов на четырёх стартах.
`ensemble_features.py` объединяет лучшие полные модели с v2, ограничивая
долю v2 снизу 25%. Фактический выбранный вес v2 — 33,56%. Веса подбирались
по июлю–августу, августу–сентябрю и сентябрю–октябрю; оценки на них не являются
независимыми тестами. Октябрь — ранее исследованная одномесячная диагностика.

Результаты ансамбля: 0,84457; 0,89231; 0,89529; 0,90855 соответственно.
Цель 0,92–0,95 локально не достигнута. Скор на сайте для v4 неизвестен.
Основной кандидат v4 — `outputs/studio/v4/submission_ensemble.csv`.
Проверенный сайтом лучший файл `outputs/submission_best.csv` не заменяется
до получения нового реального результата выше 0,88882.

Для маршрута 5 в истории нет target, в GTFS также нет его рейсов. Декабрьский
флаг запуска сам по себе не задаёт объём посадок, поэтому основной вариант
сохраняет ноль; это явное ограничение холодного старта.

На сервере модели, обучающая матрица, кеши, метрики и отчёты находятся в
`outputs/v4`. Для воспроизведения: `feature_models.py`, затем
`ensemble_features.py`, с тем же `TRAM_DATA_DIR` и распакованным архивом
признаков в `data/features`.
