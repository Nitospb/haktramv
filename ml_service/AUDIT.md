Проверено 27 сентября 2026 по шестистраничному PDF «ИИ-прогноз загрузки трамвайных маршрутов». Задание использовано как источник требований, а не как разрешение на внешние действия.

**Вывод:** готов запускаемый Docker-сервис сохранённого лучшего прогноза с API и демонстрационным интерфейсом. Все требования к полноценному диспетчерскому продукту пока не закрыты. В PDF WAPE-score >0,88 соответствует максимальным 10 баллам за качество; сообщённый публичный 0,89402 попадает в этот диапазон, но остальные критерии оцениваются отдельно.

## Что сдавать сейчас

1. Ссылку на `ml_service/README.md`: запуск Docker, API, схема, замеры и ограничения.
2. `ml_service/artifacts/manifest.json` и исходный код моделей в корне репозитория.
3. `ml_service/artifacts/sources.json` со ссылками на внешние источники.
4. Лучший `outputs/submission_best.csv` (уже оценён платформой); API выдаёт тот же файл.

Локальная ссылка localhost доступна только на машине, где запущен контейнер. Для жюри предоставляется репозиторий с Docker Compose; публичный веб-хостинг этим изменением не развёрнут.

## Приоритеты дальнейшей разработки

- Производственный прогноз на новые даты: контракт входных признаков, cutoff-логика, версия модели, воспроизводимое переобучение без скрытых target.
- Остановочная модель: качественная геопривязка транзакций и телематики, подтверждённые target, учёт изменений трассы и новых маршрутов.
- Реальный дорожный трафик: лицензированный исторический источник скоростей/пробок с нужной временной и пространственной детализацией и абляцией эффекта.
- Для диспетчерских решений: вместимость вагонов, фактический выпуск, посадки/высадки; оценка загрузки салонов требует этих дополнительных данных.

Поскольку обучающий период и будущие внешние признаки фиксированы, текущая точность не является обещанием такого же качества на следующем году или другом городе.
