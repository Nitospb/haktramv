# Районная погода для трамвайной модели

Источник: [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api),
явно выбран ECMWF IFS, глобальная сетка около 9 км. Координаты всех 119 районов взяты
из исходного `calendar_weather_features_daily_by_district.csv`, а не из геокодера.
Это модельный метеоархив, не отдельные наблюдения метеостанции в каждом районе.
Соседние районы могут иметь одну ячейку. Подстройка температуры под высоту местности
отключена (`elevation=nan`), чтобы не создавать искусственные пространственные различия.

Период по умолчанию 2025-01-01 — 2025-10-31: обучение и временная CV конкурса.
Даты меняются аргументами; IFS доступен с 2017, автоматическая загрузка всей
десятилетней истории здесь не выполняется. Существующие исходные файлы не изменяются.

Высота снега (`snow_depth`, метры) в IFS имеет пропуски. По запросу пользователя она
целиком заменяется по точному часовому timestamp из уже скачанной `center`-серии ERA5-seamless
в `data/weather_zones_hourly.parquet`. Это общегородской показатель, одинаковый
для всех районов, с отдельным `snow_depth_source`. Нет заполнения соседним временем,
нулём или будущим значением. Вне периода исходной серии остаётся пропуск.
Снегопад (`snowfall`, сантиметры за предшествующий час) остаётся районным IFS.

## Запуск

Из корня проекта:

```sh
external_features/.venv/bin/python experiments/zonal_weather/download_districts.py
external_features/.venv/bin/python -m pytest experiments/zonal_weather/test_district_weather.py -q
```

Результаты в `district_weather_2025/`: почасовой Parquet, дневной Parquet/CSV,
соответствие районов погодным ячейкам, JSON-отчёт о качестве и raw HTTP cache.
Также создаётся `calendar_weather_features_daily_by_district.parquet`: календарь
из исходного файла за тот же период с полностью заменёнными погодными колонками.
Календарь перенесён без исправлений, включая исходную уверенность школьных каникул;
его перенос не означает повторную проверку первичных календарных источников.

## Покрытие остановок

`check_stop_weather_coverage.py` запросил у того же API координаты погодной ячейки
для каждой из 314 остановок десяти целевых маршрутов. Нужны всего 9 ячеек;
все они уже присутствовали среди первых 91 скачанных районов. Все 119 районов
соответствуют 19 ячейкам. Проверка не угадывает административный район по ближайшему
центру: она сопоставляет остановку прямо с ячейкой модели.
`weather_hourly_target_route_cells.parquet` содержит только 9 нужных ячеек
(65 664 строки за январь–октябрь). `stop_route_weather_cells.csv` хранит привязки,
`route_weather_cell_weights.csv` — доли уникальных остановок маршрута в ячейках,
не доли пассажиров. Высота снега — одна общегородская серия во всех ячейках.
Повторный запуск использует кэш с проверкой SHA-256. Единицы каждого поля,
параметры запросов, даты загрузки и хэши записаны в отчёте.
Все timestamp имеют timezone Europe/Moscow. Ключи: район × timestamp/date.
Суммы осадков за день требуют 24 непустых часовых значения; группировка по метке
часа API (осадки описывают предыдущий час). Код погоды за день — мода,
при равенстве частот выбирается минимальный код. Первое изменение температуры
за 24 часа в каждом районе отсутствует по определению.

Пороги дневных флагов: дождь/осадки ≥0.1 мм, снегопад ≥0.1 см,
сильный дождь ≥20 мм дождя/сутки, сильный снег ≥5 см/сутки,
мороз Tmin<0°C, жара Tmax≥30°C. Это признаки, не официальные предупреждения.

## Использование без утечки

Все погодные значения здесь **observed**, не known_in_advance. Ретроспективный архив
не даёт гарантированного времени публикации исторической записи. Нельзя подставлять
фактическую погоду целевого дня в прогноз, сделанный заранее. Для будущего нужны
архивные прогнозы на момент origin либо климатология/лаги, доступные до origin.
Ноябрь–декабрь 2025 по умолчанию не скачиваются. Этот сборщик сам не подключает
новые таблицы к модели и не изменяет сабмишены.

[Условия](https://open-meteo.com/en/terms): данные CC BY 4.0 с атрибуцией Open-Meteo/ECMWF;
бесплатный API предназначен для некоммерческого использования. Ограничения:
600 вызовов/минуту, 5000/час, 10000/сутки; стоимость длинных многоточечных запросов
учитывается с повышающим коэффициентом. Запросы последовательные, минимум 30 секунд,
с таймаутом и ограниченными повторами; HTTP 429 не обходится сменой адреса/учётки.
