# Погода по зонам и история валидаторов без будущих событий

Лучший public-score остаётся 0.87781. Предыдущая смесь CatBoost/XGBoost
получила 0.87735. Здесь отдельный эксперимент; старые файлы не меняются.

## Погода

314 уникальных остановок маршрутов 1,5,7,11,12,17,25,26,28,50 сгруппированы
по координатам в шесть зон. Представители — реальные остановки около
центров кластеров. Запросы Open-Meteo ERA5-Seamless дали только **четыре
разные ячейки** для этих зон; повторные ячейки объединены. Ещё одна точка
в центре Москвы используется как контроль. Это сеточная модель погоды,
не измерения непосредственно у каждой остановки.

Сбор: 2022-01-01–2025-10-31, 168000 почасовых строк (4 ячейки + центр),
Europe/Moscow. Погода после последнего обучающего месяца не скачивалась.
Получены 11 численных погодных параметров без пропусков. Ветер м/с,
осадки мм, снегопад см, снежный покров м. Осадки в API относятся к
предшествующему часу; daily-файл содержит средние почасовые значения,
а не подписанные как суточные суммы. Для прошлых 7/28 суток такое
представление одинаково применяется при обучении и прогнозе.

Привязка маршрута — доля его уникальных остановок в каждой ячейке.
Пассажиропоток при выборе точек и весов не используется.

В модель не передаётся фактическая погода прогнозируемой даты:

- сезонный профиль из **2022–2023**, сглаженный по календарю ±14 дней;
- средние последних доступных 7/28 дней до forecast origin с запасом 6 дней
  на публикацию реанализа;
- дальность прогноза и возраст погодной информации.

Важно: скачан текущий ретроспективный реанализ. Его исторические версии
не восстановлены. Запас 6 дней устраняет заглядывание в будущие **даты**,
но не доказывает отсутствие более поздних исправлений самого источника.
Для строгого production-backtest нужен архив версий/прогнозов с issued_at.

## Транзакции, выпуск и валидаторы

Сырьё: 62.4 млн строк исходных файлов, обработка отдельно от обучения.
`input_date_time` **не используется для фильтрации**: README организаторов
прямо предупреждает о битых/будущих значениях. Первая пробная фильтрация
по нему отменена, обучение остановлено и агрегаты пересчитаны.

Используется `tran_date_time`, январь–октябрь 2025; ноябрьский хвост
исключён. Поле available_at в этих агрегатах — **предположение завершения
часа/дня по event time**, не достоверное время загрузки. Гарантируется
отсутствие будущих событий, но реальную онлайн-задержку доставки проверить
по данному архиву невозможно.

Признаки:

- количество наблюдаемых бортовых номеров, валидаторов, выходов;
- фактическая доля успешных и отказавших операций;
- интервалы между последовательными валидациями одного вагона в пределах
  суток и количество интервалов >=15 минут;
- доля устройств с наблюдениями, хотя бы одной успешной операцией и со
  всеми успешными операциями за предыдущие семь полных дней;
- **для каждого конкретного валидатора**: success_pct_7d и число операций,
  отдельные входные столбцы CatBoost. Не только агрегированные показатели!

В полном архиве обнаружено 3074 идентификатора валидаторов. Словарь каждой
CV-модели содержит только устройства, наблюдавшиеся до её cutoff.
Проценты: 0–100. Если нет операций за неделю, success_pct неизвестен (NaN),
а count=0 для устройства, известного на этом маршруте за последние 84 дня.
Будущие/неизвестные устройства не считаются сломанными. Нет ручного
удаления устройства за высокий процент отказов: полезность оценивает модель.

По README `validation_result=1` — успех, остальные коды — отказы операции.
Подтверждённого справочника «этот код означает физическую поломку устройства»
нет. Данные сохраняют это различие. Отсутствие валидаций не равно
доказанной задержке движения; интервалы так и названы intervalidation_gap.

## Автомобильные пробки

Реальный архив скоростей/загруженности за 2025 год получить без доступа
к поставщику пока не удалось. В доступных транзакциях нет GPS/скорости.
Текущие пробки не подставляются задним числом; транзакционные показатели
не переименовываются в дорожную загруженность.

Найден TomTom Traffic Stats: документация указывает историческое покрытие
России с 2014, но требуется отдельный ключ MOVE и проверка доступности
конкретных дат/географии. Аккаунт/подписка не создавались.
Готова функция `join_road_traffic_asof`: принимает route, event_at,
available_at, congestion_index и соединяет только данные, опубликованные
к origin. Известные будущие фактические пробки и ещё не опубликованные
наблюдения не попадут в модель. Без исходного архива эта группа не обучается.

## Проверка моделей

Обучение только на Mac Studio. Пять вариантов: календарь без погоды,
погода центра, зональная погода, зональная+операционные агрегаты,
зональная+операционные агрегаты+индивидуальные валидаторы.
Старые фактические погодные признаки и исторические профили, рассчитанные
на cutoff и присоединённые ко всем прошлым строкам, удалены из эксперимента.
Новые признаки строятся относительно собственного origin каждой строки.
Общие seed2025, MAE, depth8, 550 деревьев, без early stopping на внешних метках.
Дальность обучающих примеров 1–61 дней выбирается фиксированным RNG по датам,
без зависимости от target. На каждом проверочном окне один общий origin.

10 последовательных перекрывающихся окон по 61 дню. Первые пять выбирают
вариант, последнее сравнивает его с календарным контролем. Эти периоды уже
изучались, полностью независимого зимнего holdout нет. Дельта к новому
контролю не равна ожидаемой дельте к public-best.

Тесты специально меняют будущие исходные значения на экстремальные и
проверяют, что прогнозные признаки до этих дат не меняются.

## Запуск

Из корня проекта, локально (только подготовка данных):

```sh
external_features/.venv/bin/python experiments/zonal_weather/build.py
external_features/.venv/bin/python experiments/zonal_weather/aggregate_ops.py
external_features/.venv/bin/python -m pytest experiments/zonal_weather/test_features.py -q
```

Нужны pandas, numpy, pyarrow, duckdb, pytest и HTTP-модуль из
`external_features`. Raw API responses кэшируются с SHA256, повторный сбор
погоды не скачивает их заново. `train.py` запускается на Studio, читает
`~/tram-baseline` и данные из `~/tram-experiments/zonal_weather/data`.
